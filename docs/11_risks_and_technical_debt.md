# 11. Risks and Technical Debt

This section systematically identifies, categorizes, and evaluates the known technical risks and accumulated technical debt within the PurpleLedger platform. By maintaining an explicit ledger of these systemic liabilities, we ensure that architectural trade-offs remain visible to stakeholders and can be actively managed, prioritized, and mitigated during future development cycles.

The identified risks are categorized into three primary domains: **Business Risks** (affecting compliance and core logic), **Technical Risks** (affecting operability, scale, and system resilience), and **Technical Debt** (suboptimal implementations impacting maintainability).

## 11.1 Business Risks

Business risks encompass systemic gaps or incomplete domain logic that could directly compromise the platform's adherence to regulatory standards (such as the Nigeria Tax Act) or distort financial accuracy.

| Risk                                                          | Severity | Impact                                                                                                                                                                                                       | Mitigation Strategy                                                                                                                                                                 |
| :------------------------------------------------------------ | :------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Missing Optional Authentication Middleware Implementation** | High     | `is-optional-authenticated-user.middleware.ts` still contains a `TODO` body. Endpoints that allow anonymous access may not consistently populate request context for authenticated callers.                  | Implement optional token extraction and validation using the central auth service so request context is safely populated when credentials exist and explicitly anonymous otherwise. |
| **Incomplete Reporting-Currency Context**                     | High     | Bookkeeping service TODOs currently default balance updates to the accounting entity's functional currency rather than the active reporting-context currency. This can distort future multi-reporting flows. | Resolve the current reporting context before balance adjustment and pass the correct currency into ledger-balance creation and adjustment routines.                                 |

## 11.2 Technical Risks

Technical risks include architectural bottlenecks, missing access layers, and unhandled edge cases that threaten the runtime stability, performance, and scalability of the platform.

| Risk                                           | Severity | Impact                                                                                                                                                                                                      | Mitigation Strategy                                                                                                                                            |
| :--------------------------------------------- | :------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Journal Line Metadata Still Underspecified** | Medium   | `journal-line.entity.ts` currently hardcodes `meta: null`, and `journal-line.types.ts` still notes that metadata nullability should be tightened. This limits future support for richer posting provenance. | Define the allowed journal-line metadata shape, normalize nullability, and update mappers and persistence models together.                                     |
| **Generated API Artifact Drift**               | Medium   | API route and Swagger artifacts now live under `generated/`. Manual edits or stale generated output can cause the runtime routes, OpenAPI contract, and TypeScript controllers to disagree.                 | Treat `generated/routes.ts` and `generated/swagger.json` as build outputs from `tsoa spec-and-routes`; regenerate them during build/CI and avoid manual edits. |

## 11.3 Technical Debt

Technical debt represents conscious or unconscious implementation shortcuts that significantly increase the cognitive load on developers and the long-term cost of system maintenance, although they may not immediately threaten stability.

| Debt                                              | Impact                                                                                                                                                                                            | Refactoring Plan                                                                                                                                                      |
| :------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hardcoded Ledger Account Code Generation**      | The `LedgerAccount` entity relies on account-class helpers and explicit predecessor codes. This is deterministic, but still requires careful service orchestration to assign the next valid code. | Continue centralizing code assignment in account services and add regression coverage for every account class and control/sub-account boundary.                       |
| **Lack of Localization Support in Value Objects** | Fundamental domain validation errors within `MoneyVO` (`money.vo.ts`) still carry an explicit i18n TODO.                                                                                          | Decouple error string literals from the domain layer entirely by throwing strongly typed errors that hook into the global i18n translation dictionary via middleware. |
